# Соглашения разработки Ear Lab

## Область проекта

Ear Lab — клиентское приложение React + TypeScript + Vite для распознавания ступеней мажора. Использовать Tone.js для звука, Tonal.js для музыкальной теории, обычный CSS для интерфейса. Не добавлять backend, авторизацию, другие упражнения и UI-фреймворки без отдельного запроса.

Для ступени доступны «Эмбиент» и «Пианино». Эмбиент — мягкий синтезированный pad с ослабленными верхними гармониками и собственным low-pass-фильтром: его срез следует за основной частотой ноты, чтобы сохранять высоту и смягчать яркость на всём протяжении звучания. Пианино — Tone.Sampler с локальными сэмплами Salamander, без фильтра и реверберации. Тёплая непрерывная тоника с фильтром и лёгкой реверберацией общая для обоих тембров. Ступень сохранять отчётливой; не добавлять расстройку высоты или выраженный хорус. Дождаться готовности реверберации и выбранного инструмента перед первым воспроизведением и освобождать эффекты и сэмплер при размонтировании.

## Границы модулей

- `src/music/` — чистые функции, типы и reducer. Не импортировать React, DOM и Tone.js. Строить гамму через Tonal.js, учитывать альтерации и номера октав.
- `src/audio/` — только воспроизведение. Принимать готовые имена нот; не генерировать задания и не проверять ответы. Инициализировать Web Audio после действия пользователя. Обеспечивать отмену таймеров и освобождение инструментов.
- `src/hooks/` — связывать настройки, музыкальную модель и аудио. Защищать состояние от завершения устаревших асинхронных запросов.
- `src/components/` — отображение и обработчики через props. Не обращаться к Tone.js и не вычислять гаммы.
- `App.tsx` — собирать страницу, не переносить в него бизнес-логику.
- Общие стили — `index.css`, стили интерфейса — `App.css`. Не использовать inline-стили кроме вычисляемых параметров визуализации.

## Инварианты упражнения

- Включена хотя бы одна ступень и хотя бы один регистр. По умолчанию активны нижняя, основная и верхняя октавы относительно тоники в регистре 4. Выбирать равновероятно из всех включённых пар «ступень × регистр»; ответ остаётся номером 1–7 независимо от октавы.
- По нажатию «Слушать» включается тихий непрерывный тонический фон; поверх него звучит ступень в выбранном регистре. Для До мажора полный диапазон C3–B5, для Си мажора B3–A#6. Повтор сохраняет также октаву ноты.
- Фоновую тонику сохранять в общем басовом регистре F#2–F3: например, C3 для До мажора, B2 для Си мажора. Фон не выше нижней тоники; нижняя I ступень может совпасть с ним в унисон. Переключение октав ступеней не меняет высоту фона. Высоту фона определяет `src/music/`, аудиодвижок получает готовую ноту.
- У низкого тонического фона должны быть мягкие верхние гармоники и достаточная громкость для небольших динамиков; чистая тихая синусоида в этом регистре плохо различима. Проверять слышимый сигнал после завершения ступени, а не только флаг активности.
- При изменении громкости сохранять баланс фона и ступени; проверять пиковый уровень их совместного звучания, чтобы он оставался ниже цифрового перегруза.
- При коротком нажатии ступень звучит одну секунду с ненулевым sustain, затем плавно затухает. При удержании кнопки мышью, касанием или Space/Enter ступень звучит до отпускания. Разрешать ответ после завершения затухания.
- Прослушивание, повтор и переход к новому вопросу выполняет одна основная кнопка: «Слушать» → «Повторить» → «Следующее задание». Не добавлять отдельные кнопки повтора или «Дальше». После проверки кнопка «Проверить» скрывается.
- Основная кнопка поддерживает удержание во всех трёх состояниях. Не создавать дополнительный вопрос из последующего `click`; отпускание вне кнопки, `pointercancel`, потеря фокуса, скрытие вкладки и размонтирование завершают удержание.
- Смена тембра отменяет текущую ступень и вопрос, сохраняет счёт и тонический фон. Сэмплы грузить лениво, кешировать в аудиодвижке и корректно обрабатывать отмену, ошибку и повтор загрузки. Пока выбранное пианино загружается, блокировать прослушивание; переключение обратно на эмбиент остаётся доступным.
- Пианино при удержании естественно затухает, без искусственного зацикливания записи. Сэмплы и сведения об авторе/лицензии хранить в `public/audio/piano/`, ссылки формировать через `import.meta.env.BASE_URL` для GitHub Pages. Атрибуция должна быть доступна на компьютере и телефоне.
- Фон сохраняется во время ответа, проверки, повторов и перехода к следующему вопросу. Не перезапускать его на каждом вопросе. Кнопка выключения останавливает только фон; следующее прослушивание включает его снова.
- «Повторить» сохраняет вопрос. Новый вопрос создаётся после перехода дальше или сброса настроек.
- До окончания прослушивания ответ заблокирован. После проверки ответ нельзя изменить или засчитать повторно.
- Правильная нота и номер ступени не показываются до проверки, в том числе в доступных подписях.
- Смена настроек отменяет текущую ступень, сбрасывает выбор и обратную связь; счёт сессии сохраняется. При смене тональности активный фон плавно перестраивается, при смене доступных ступеней продолжает звучать. Выключенный фон смена настроек не включает.
- При размонтировании освобождать аудиоресурсы и отменять отложенные действия.

## Качество

- Использовать строгую типизацию, явные props и тип `Degree` для ступеней. Избегать `any`.
- Сохранять русский язык интерфейса, доступность кнопок, видимый focus, достаточные размеры сенсорных элементов и адаптацию от 320 px.
- Анимации должны учитывать `prefers-reduced-motion`; цвет не должен быть единственным способом сообщить результат.
- При изменении логики дополнять содержательные тесты инвариантов. Не писать тесты, повторяющие детали оформления.
- Перед завершением изменений запускать `npm test` и `npm run build`. Для изменений интерфейса проверять компьютер и телефон, если доступен браузер.
- Держать `README.md`, команды и описание архитектуры в соответствии с реализацией. Фиксировать зависимости в `package-lock.json`.
