# Ear Lab

Веб-приложение для тренировки музыкального слуха: распознавание ступеней мажорной гаммы на синтезированном фортепиано. React, TypeScript, Vite, Tone.js, Tonal.js и обычный CSS. Backend и регистрация не нужны.

## Запуск

Нужен Node.js 22.12+ или 24 LTS и npm. Проект проверен на Node.js 24.

```bash
npm install
npm run dev
```

Откройте адрес из терминала, обычно **http://localhost:5173**. Если порт занят, Vite предложит следующий свободный порт.

Для просмотра с телефона в той же Wi-Fi сети:

```bash
npm run dev -- --host 0.0.0.0
```

Откройте на телефоне адрес `Network`, который напечатает Vite. Разрешите локальную сеть, если это потребуется системе. На телефоне может потребоваться отключить беззвучный режим.

## Как тренироваться

1. Выберите одну из 12 тональностей и доступные ступени. Хотя бы одна ступень должна оставаться включённой.
2. Нажмите «Слушать задание». Сначала прозвучит тоника, после паузы — случайная доступная ступень той же мажорной гаммы.
3. При необходимости нажмите «Повторить»: прозвучит та же пара нот.
4. Выберите ответ 1–7 и нажмите «Проверить». Приложение покажет правильную ступень и название ноты.
5. Нажмите «Дальше» для нового задания.

Смена тональности или набора ступеней останавливает звук и сбрасывает текущий вопрос. Счётчик верных ответов хранится только до перезагрузки страницы. Задания выбираются равновероятно; одна ступень может выпасть несколько раз подряд.

Звук начинается только после нажатия: это требование браузеров к Web Audio. Тембр создан FM-синтезом с быстрым началом и затуханием, без внешних аудиосэмплов; это приближение к фортепиано. Правильная ступень и нота остаются скрытыми до проверки. Все ноты находятся в восходящей октаве от тоники четвёртой октавы в научной нотации (`C4` — среднее до); для высоких тоник гамма переходит в пятую октаву.

## Проверки и сборка

```bash
npm test             # музыкальные интервалы, жизненный цикл задания, отмена звука
npm run build       # TypeScript и production-сборка в dist/
npm run preview     # локальный просмотр production-сборки
```

Тесты проверяют интервалы во всех тональностях, диезы/бемоли и переход через октаву, выбор из доступных ступеней, защиту от повторного зачёта и отмену воспроизведения. Реальное качество звука и поведение конкретного мобильного браузера проверяются вручную.

## Публикация на GitHub Pages

Репозиторий: [peasemaker/ear-lab](https://github.com/peasemaker/ear-lab).
Ожидаемый адрес после успешной публикации: **https://peasemaker.github.io/ear-lab/**.

1. Откройте [Settings → Pages](https://github.com/peasemaker/ear-lab/settings/pages).
2. В `Build and deployment → Source` выберите **GitHub Actions**.
3. Закоммитьте `.github/workflows/deploy.yml` и обновлённый `README.md`, затем отправьте изменения в ветку `main`.
4. Во вкладке [Actions](https://github.com/peasemaker/ear-lab/actions) дождитесь успешного завершения **Deploy Ear Lab to GitHub Pages**. Ссылка на сайт появится в результате deployment и в настройках Pages.

Workflow автоматически запускает `npm ci`, тесты, сборку и публикацию `dist` при каждом push в `main`. Также его можно запустить вручную через `Actions → Deploy Ear Lab to GitHub Pages → Run workflow`. Личные токены и ветка `gh-pages` не нужны; используются стандартные разрешения `GITHUB_TOKEN`. Папки `node_modules` и `dist` в репозиторий не добавляются.

Базовый путь сборки берётся из метаданных GitHub Pages через `actions/configure-pages`: `/ear-lab/` для стандартного адреса, `/` для собственного домена. Локальная разработка сохраняет путь `/`, менять `vite.config.ts` не требуется.

Проверить сборку под стандартный адрес локально можно так:

```bash
npm run build -- --base=/ear-lab/
npm run preview -- --base=/ear-lab/
```

Откройте `http://localhost:4173/ear-lab/` или адрес с портом из терминала.

Для собственного домена укажите его в `Settings → Pages → Custom domain`, настройте DNS у регистратора по [инструкции GitHub](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site) и включите `Enforce HTTPS`, когда опция станет доступна. После подключения домена повторно запустите workflow, чтобы пересобрать сайт с новым базовым путём. При публикации через этот workflow файл `CNAME` не требуется.

## Архитектура

```text
src/
  music/
    majorScale.ts        # гаммы Tonal.js, ступени, генерация вопроса, имена нот
    session.ts           # чистый reducer: ответ, проверка, счёт, состояния
    *.test.ts            # тесты музыкальной логики и состояний
  audio/
    piano.ts             # Tone.js, последовательность нот, отмена, очистка
    piano.test.ts        # тесты порядка и отмены воспроизведения
  hooks/
    useExercise.ts       # связывает настройки, reducer и аудиодвижок
  components/
    SettingsPanel.tsx    # тональность и доступные ступени
    ListeningPanel.tsx   # прослушивание и повтор
    AnswerPanel.tsx      # выбор ответа и обратная связь
    Icon.tsx             # общие SVG-иконки
  App.tsx                # композиция страницы
  App.css                # интерфейс и адаптивная сетка
  index.css              # базовые стили и типографика
```

Музыкальная логика не зависит от React или Web Audio; аудиодвижок не знает об интерфейсе и проверке ответа. React-компоненты получают данные и обработчики через props. Соглашения для дальнейшей разработки — в [AGENTS.md](./AGENTS.md).

Интерфейс адаптируется к ширине от 320 px, поддерживает клавиатурную навигацию, объявления результата для скринридеров и `prefers-reduced-motion`. Шрифт Manrope загружается из Google Fonts; при отсутствии сети используются системные шрифты. Аудио работает локально.
